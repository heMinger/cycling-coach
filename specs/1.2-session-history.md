# 1.2 刷新保留对话 — 方案调研与实施

## 行业参考

### ChatGPT / Claude / Gemini
- **全部服务端持久化**：对话历史存服务器，前端 onload 通过 API 拉取
- **localStorage 仅用于 UI 状态**：当前会话 ID、草稿、滚动位置
- **不依赖客户端存储**：换设备/浏览器可恢复对话
- **来源**：CSDN 分析文章 + Hacker News 讨论

### OpenHands / CopilotKit（2025-2026）
- onload → fetch session API → 渲染消息 → 恢复草稿（sessionStorage）→ 重连 WebSocket
- 关键：区分空会话（不展示）和有内容的会话
- 来源：OpenHands PR #13380、CopilotKit v4.0.0

## 方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. localStorage 全量存储 | 前端存所有消息到 localStorage | 实现简单，无需后端 | 5MB 上限、隐私问题、换设备丢失 |
| B. 服务端持久化 + onload 拉取 | 后端存 SQLite，前端 /messages 接口 | 跨设备、无容量限制、行业标准 | 需后端接口 |
| C. 混合：LangGraph checkpoint | 直接用 checkpoint 恢复消息 | 原生支持 interrupt 恢复 | checkpoint 可能过时，LD 依赖 |

**选择方案 B**：与 ChatGPT/Claude 一致，项目已有 `conversations` 表和 `memory.py` 存储。

## 实施计划

1. ✅ `memory.py`：新增 `get_session_messages()` 函数
2. ✅ `api.py`：新增 `GET /messages?session_id=xxx`，同时返回 interrupt 状态
3. ✅ `index.html`：DOMContentLoaded 时 fetch 历史并渲染 + 恢复 interrupt 卡片

## 实施结果

- `GET /messages` 返回 `{messages: [...], interrupt: null|{type, plan, message}}`
- 前端 loadHistory() 在页面加载时自动调用
- 如存在 pending interrupt，自动恢复确认卡片或输入提示
